## 一、空间耦合 LDPC 是怎么回事（调研）

### 1.1 从分组码到耦合链

普通 LDPC **分组码**由一张固定的校验矩阵 `H`（Tanner 图）定义，各码字相互独立。
**空间耦合 LDPC** 的思路是把一串原本独立的 LDPC 分组码（称为**分量码 /
component code**，由原型图 / 基矩阵 `B` 描述）沿"空间"方向**耦合**起来，
形成一条长链。它最早以 **LDPC 卷积码**（Felström & Zigangirov, 1999）的形式出现，
后来 Kudekar–Richardson–Urbanke（2011）从原型图角度系统化，并证明了它惊人的性质。

### 1.2 边扩展（edge spreading）与耦合

设分量码的基矩阵为 `B`（尺寸 `m_b × n_b`）。给定**耦合宽度 / 记忆** `w`，
把 `B` 拆成 `w+1` 个分量矩阵：

```
B = B_0 + B_1 + ... + B_w        （每条边恰好分到一个分量，称为 edge spreading）
```

再把这些分量沿对角线错位排列，得到一个**带状（band-diagonal）**的耦合校验矩阵。
对耦合长度 `L`（链上空间位置数），耦合校验矩阵的分块结构为

```
H_SC[i, t] = B_{i-t}      当 0 ≤ i-t ≤ w     （否则为 0）
             i = 0 .. L+w-1   （校验位置 / 行块）
             t = 0 .. L-1     （变量位置 / 列块）
```

也就是说：**第 t 个变量位置**通过 `B_0, B_1, …, B_w` 分别连到
**校验位置 t, t+1, …, t+w**。本实现 `demo.py` 打印出来的真实带状结构（L=12, w=2）：

```
    012345678901   <- 变量位置 t
i= 0 B...........
i= 1 BB..........
i= 2 BBB.........
i= 3 .BBB........
   ...（对角带）...
i=11 .........BBB
i=12 ..........BB  <- 终止校验
i=13 ...........B  <- 终止校验
```

### 1.3 终止（termination）与码率损失

注意行块比列块多了 `w` 个（共 `L+w` 个校验位置，`L` 个变量位置）。
末尾这 `w` 个额外的校验行块就是**终止**带来的：它们让链两端的变量受到
**更强的约束**（边界处的校验节点"度更低、更可靠"）。代价是产生少量**码率损失**：
耦合码率 `R_L` 略低于分量码率 `R`，且

```
L → ∞ 时，R_L → R           （码率损失 ∝ w/L，随 L 增大而消失）
```

### 1.4 阈值饱和（threshold saturation）——SC-LDPC 的核心威力

这是 SC-LDPC 最重要的理论结果（KRU 2011/2013）：

> **终止 SC-LDPC 系综在置信传播（BP）译码下的门限，会"饱和"到其分量码系综在
> 最优 MAP 译码下的门限。**

通俗地说：耦合 + 终止这一招，**几乎免费**地把次优的迭代 BP 译码器的性能，
提升到了最优 MAP 译码器的水平，从而**逼近信道容量**。而且它对各种二进制对称
信道（BEC/BSC/AWGN）普遍成立，对原型图 LDPC 也成立。

### 1.5 译码波（decoding wave）

阈值饱和的物理机制是**译码波**：终止造成的两端边界先被可靠译出，
随后这种"可靠性"像波一样**从两端向中间传播**，逐位置地把整条链译出来。
本实现 `demo.py` 在阈值附近真实地展示了这一现象（每位置比特错误数）：

```
信道硬判决:        330 372 329 371 352 353 346 332 370 333 265 283
 2 次BP迭代后:     199 288 316 337 344 347 312 295 334 298 235 201
 5 次BP迭代后:      75 182 305 356 363 362 314 320 291 234 164  36
10 次BP迭代后:      49 157 264 350 367 365 330 340 270 185  75  10
30 次BP迭代后:      35 143 220 279 254 255 216  89  53  10   2   0
```

可以清楚看到错误从**两端被逐步"吃掉"**（左端 35,143… 右端 …2,0），中间最后收敛。

### 1.6 滑窗译码（sliding-window decoding）——低时延

因为译码波是局部、从左到右推进的，所以不必把整条长链一次性载入译码器。
**滑窗译码**只在一个 `W` 个位置的窗口内做 BP，输出窗口最左（最老）位置后，
窗口右移一格。于是**译码时延/存储只正比于 `W` 而非 `L`**，这是 SC-LDPC
能用于流式、长链场景的关键工程优势。本仓库实现了该译码器（`SCLDPCCode.decode_windowed`）。

## 二、基于 5G NR 标准 LDPC 的构造

### 2.1 5G NR LDPC 回顾（3GPP TS 38.212 §5.3.2）

5G NR 采用 **准循环（QC）LDPC**，由两张基图定义：

| 基图 | 尺寸 `m_b × n_b` | 信息列 `K_b` | 打孔 | 最低码率（满基图） |
|------|------------------|--------------|------|---------------------|
| BG1  | 46 × 68          | 22           | 前 2 列 | 1/3                 |
| BG2  | 42 × 52          | 10           | 前 2 列 | 1/5                 |

- **提升（lifting）**：基矩阵每个元素是 `-1`（`Z×Z` 全零块）或一个移位值
  `v∈[0,Z)`（`Z×Z` 单位阵循环右移 `v`）。`Z` 有 51 种取值，分 8 组（`i_LS`）。
- **打孔**：前 2 个信息列（`2Z` 比特）系统位不发送（内建打孔），是高码率的关键。
- **可高效编码的校验结构**：前 4 行 × 前 4 个校验列构成一个"核"（双对角），
  第 5 行起是 shift=0 的**单位对角累加器**。本仓库 `analyze_bg.py` 在真实
  BG1/BG2 数据上验证了该结构，因此编码器（`nr_ldpc.py`）对两张基图都严格成立：

  ```
  H_parity = [ C  0 ]     C : 4×4 块"核"
             [ E  I ]     I : 单位对角累加器
  p_core = C^{-1} · s_core         （一次小规模 GF(2) 求逆，预计算）
  p_i    = s_i  ⊕  E_i · p_core     （i≥4，纯累加）
  ```

> 真实基图数据来自开源仓库 [manuts/NR-LDPC-BG](https://github.com/manuts/NR-LDPC-BG)
> （3GPP TS 38.212 基矩阵，移位值已对 `Z` 取模），见 `data/`。

### 2.2 本实现的耦合方案：系统位边扩展

直接对整张 `B` 做边扩展会破坏 5G 的可编码校验结构（`B_0` 的校验部分将不可逆，
失去逐位置编码能力）。为了**既忠于 5G NR、又保持高效编码**，本实现采用
**"系统位边扩展"**：

- **只把系统位（前 `K_b` 列）的边**随机分配到 `B_0 … B_w`；
- **整个校验部分（后 `m_b` 列）保留在 `B_0`**。

于是 `B_0` 的校验部分 = 完整的 5G NR 双对角结构，**每个空间位置都能用标准 5G
编码器递推求解校验位**。校验位置 `i` 的方程为

```
Σ_{t=i-w}^{i}  (B_{i-t} 的系统位部分)·sys_t   ⊕   (B_0 的校验部分)·p_i  =  0
```

即：先由"本位置 + 前 w 个位置"的系统位算出行综合征 `S_i`，再用 5G 的
`solve_parity(S_i)` 解出本位置校验位 `p_i`（`sc_ldpc.py::encode`）。

### 2.3 终止与码率

链尾 `w` 个位置的**系统位置零**即可满足那 `w` 个终止校验（它们只约束尾部系统位）。
于是：

```
信息位  K   = (L−w)·K_b·Z
发送位  N   = (L−w)·(n_b−2)·Z  +  w·(n_b−K_b)·Z     （扣除每位置 2 列打孔；尾部已知零位不发送）
码率   R_L = K / N
```

以 BG2、`Z=24`、`L=30`、`w=2` 为例：`R_L ≈ 0.189`，分量码 `R = 0.200`，
差值正是 `w/L` 量级的终止码率损失。

## 四、发射机 / 接收机流程

**发射机**：随机信息比特 → `SCLDPCCode.encode` 逐位置 5G 编码 → 得到耦合码字
`c`（满足 `H_SC·c = 0`）→ 去掉打孔位与尾部已知零位 → BPSK（0→+1, 1→−1）。

**信道**：`y = x + n`，`n ~ N(0, σ²)`，`σ² = N0/2`，由 `Eb/N0` 与码率换算。

**接收机**：算信道 LLR `L = 2y/σ²`（打孔位 LLR=0，尾部已知位 LLR=+大）→
- 全图 BP（`Tanner.decode`）：在整张耦合 Tanner 图上做泛洪 BP；或
- 滑窗 BP（`decode_windowed`）：仅在 `W` 位置窗口内 BP，逐位置输出，低时延。

### 5.3 大耦合链长与阈值饱和（L = 100 / 200 / 300）

```bash
python experiments.py chain 30    # 参考
python experiments.py chain 100
python experiments.py chain 200
python experiments.py chain 300   # 各占一个进程，可并行
python experiments.py chain_plot  # 合成 exp_chain.svg
```

**为什么必须用滑窗译码器**：全图泛洪 BP 的译码波每次迭代只前进约 1 个空间位置，
要译完长为 L 的链需要 ~L 次迭代（整体 O(L²)），在 L=300 时不可行。
**滑窗译码**只在 W 个位置的窗口内做 BP、逐位置输出，**时延/复杂度只正比于 W，与 L 无关**
——这正是 SC-LDPC 可用于流式 / 任意长链的根本原因。

**阈值饱和的有限长体现**：随 L 增大，
(1) 码率损失 `w/L` 趋于 0（实测 `R`：L=30→0.189, 100→0.197, 200→0.198, 300→0.199 → 0.2）；
(2) 瀑布**收敛到一个极限**，L=100/200/300 几乎重合——超过某个 L 后再加长链不再改善门限。
另注意：**阈值以下**长链因窗口译码的错误传播 BER 略高，**阈值以上**各 L 收敛。

实测 BER（BG2, Z=16, w=2, 滑窗 W=6）：

| Eb/N0 | L=30 | L=100 | L=200 | L=300 |
|:--:|:--:|:--:|:--:|:--:|
| 0.70 | 8.5e-2 | 5.3e-2 | 4.4e-2 | 3.6e-2 |
| 0.90 | 2.1e-2 | 7.1e-3 | 5.0e-3 | 4.2e-3 |
| 1.30 | 1.6e-3 | 4.6e-4 | 3.8e-4 | 3.1e-4 |
| 1.50 | 3.4e-4 | 1.5e-4 | 1.3e-4 | 1.2e-4 |

→ L=30→100 改善大（0.9dB 处 3×），L=100→200→300 改善快速缩小，尾部(1.5dB)
`1.5e-4/1.3e-4/1.2e-4` 已基本重合 —— **门限在 L≈100–200 已饱和**。

**高码率下的大链长（BG1, R≈0.7/0.8/0.9）**：用同样的滑窗译码重做 L=30/100/200/300，
以 **BER=1e-3 处的瀑布门限 Eb/N0** 衡量（比单点 BER 比值稳健，可区分"瀑布平移"与"变陡"）：

| 码率 | L=30 | L=100 | L=200 | L=300 | L30→L300 门限平移 |
|:--:|:--:|:--:|:--:|:--:|:--:|
| **R≈0.20** (BG2) | 1.36 | 1.20 | 1.11 | 1.11 | **−0.25 dB（明显改善）** |
| R≈0.70 (BG1) | 2.58 | 2.60 | 2.59 | 2.61 | ≈0（已饱和） |
| R≈0.78 (BG1) | 3.04 | 3.01 | 3.00 | 3.00 | ≈0（已饱和） |
| R≈0.92 (BG1) | 4.36 | 4.42 | 4.48 | 4.42 | ≈0（已饱和） |

**核心发现：饱和长度 L\* 随码率升高而急剧缩短。**
- **低码率 R≈0.2**：长链才有用 —— 门限随 L 改善约 **0.25 dB**，约 **L≈100–200 饱和**；
- **高码率 R≈0.7/0.8/0.9**：各 L 曲线几乎重合（±0.05 dB 为统计噪声）—— **在 L≈30 就已饱和**，
  再加长到 100/200/300 无额外增益。

**原因**：阈值饱和填补的是 BP 与 MAP 门限之差；该差对**低码率**（强码、每位置校验多）**大**、
对**高码率**（弱码、校验少）**小**。所以低码率需要长链来逼近 MAP 门限，高码率本就接近、短链即饱和。
（注意：单看某一 SNR 点的 BER 比值会因高码率瀑布很陡而被放大，故用瀑布门限才准确。）

> 见 `exp_chain.svg`（低码率）、`exp_chain_high_70/80/90.svg`（高码率）；
> 数据 `results_exp_chain_*.json`、`results_exp_chain_high_*.json`。

### 5.4 波形级信道：PAM4 + RRC 成形（`pam4_rrc.py` / `experiments_pam4.py`）

前面各实验都是**符号级 BPSK + 直接 AWGN**（理想符号同步）。本节换成更贴近实际的
**波形级**链路：

```
编码比特 → PAM4(Gray, 2bit/符号) → 上采样 sps=4 → RRC 成形(β=0.1, span=10)
        → 波形上加 AWGN → RRC 匹配滤波 → 符号率降采样 → 软解调(LLR) → 滑窗 BP 译码
```

要点与验证：
- **PAM4 Gray 映射**：相邻电平差 1 bit；电平 `{±1,±3}/√5`（Es=1）。软解调用
  精确 log-sum-exp 求每符号 2 个比特的 LLR。
- **单位能量 RRC**：理想下匹配滤波+降采样后等效于 `y_k=a_k+n_k`（Nyquist 无 ISI、
  噪声独立）。未编码 PAM4 BER 与理论 `0.75·Q(√(0.8·Eb/N0))` 在工作区吻合（已验证）。
- **有限 span 截断**：β=0.1 拖尾长，span=10 截断带来约 0.04（rms）残余 ISI——在 LDPC
  工作区只是 ~0.5 dB 惩罚（地板只在 12 dB+ 出现，远高于工作区），是真实信道的合理体现。
- **Eb/N0 记账**：PAM4 每符号 2 比特，`σ_w² = 1/(4·R·Eb/N0)`（Es=1）。
- **PAM4 比 BPSK 低效**：相同码率下瀑布右移约 2–3 dB（每符号塞 2 bit 的代价）。

实验矩阵（**多 subagent 并行**，每码率一个 worker）：
**码率 R∈{0.5,0.6,0.7,0.8,0.9} × 耦合链长 L∈{30,100,200,300}**，滑窗译码 W=6。

```bash
python experiments_pam4.py run 0.7 100   # 单个 (R,L)
python experiments_pam4.py plot          # 每码率一张 exp_pam4_<R>.svg
```

**实测结论**（BER=1e-3 处的瀑布门限 Eb/N0，越低越好；滑窗 W=6）：

| 码率 | L=30 | L=100 | L=200 | L=300 | 最优 L |
|:--:|:--:|:--:|:--:|:--:|:--:|
| R≈0.5 | 4.31 | 4.27 | 4.31 | 4.27 | ≈持平 |
| R≈0.6 | 5.25 | 4.96 | 4.91 | 5.02 | L=100–200（≈−0.3dB） |
| R≈0.7 | 5.88 | 5.83 | 5.83 | 5.88 | ≈持平 |
| R≈0.8 | 6.75 | 6.59 | 6.52 | 6.56 | L=200（≈−0.2dB） |
| R≈0.9 | 8.38 | 8.75 | 8.44 | 8.48 | L=30 |

- **耦合链长在 0.5–0.9 这些（偏高）码率上基本无收益**：L30→L300 的门限平移都在 ±0.3 dB
  以内、且方向不一致（R0.6/0.8 略偏向 L=100–200，R0.9 略偏向 L=30），量级与蒙特卡洛
  噪声相当 —— 即**在 L≈30 就已饱和**。这与 BPSK 实验「高码率饱和长度 L\*≲30」完全一致：
  PAM4 用的 0.5–0.9 全都落在高码率区。要看到「大 L 才有用」需到低码率（≲0.3）。
- **L=300 并不一定优于 L=200**（如 R0.6/0.9）：很长的链上**窗口译码的错误传播**会反噬，
  抵消本就微小的耦合收益。
- **PAM4 的功率代价**：相同码率下 PAM4 瀑布比 BPSK 高约 2.5–4 dB（每符号 2 比特 + 电平
  更密），且代价随码率升高而增大（R0.5≈+2.5dB，R0.9≈+4dB）。
- 波形级（PAM4+RRC+匹配滤波+软解调）相对符号级 BPSK 更真实，但**不改变上述饱和结论**。

**对照组（普通 5G NR QC-LDPC）**：每张图都含一条**未耦合的 5G NR LDPC**（同码率、同提升
尺寸、全图 BP）作基线（`results_pam4_ctrl_<R>.json`）。实测 SC 相对该基线的增益（BER=1e-2）：
R0.5 +0.22dB、R0.6 +0.20、R0.7 +0.13、R0.8 +0.12、R0.9 +0.03 —— **小且随码率递减**
（这是「窗口译码的 SC」对「全图 BP 的单块码」的真实净增益；高码率 BP-MAP 间隙小故增益小）。

> 图 `exp_pam4_50/60/70/80/90.svg`（或 `results.html`）；数据 `results_pam4_<R>_<L>.json`、`results_pam4_ctrl_<R>.json`。

### 5.5 超参数热力图：码长 × 链长 × 深度（`experiments_heatmap.py`）

对码率 0.7/0.8/0.9，**网格搜索**全部组合：
- **码长** Z ∈ {16,32,64}（3GPP BG1 iLS0 提升尺寸）
- **耦合链长** L ∈ {30,100,300}
- **耦合深度** w ∈ {1,2,3}（浅耦合）

仍用 PAM4+RRC 波形信道、滑窗译码。每个 `(R,Z,L,w)` 一个进程（**多 subagent 并行**，
每个「码率×深度」一个 worker 跑 9 个 `Z×L` 单元），度量在该码率工作点 Eb/N0 处的 BER；
另含 `(R,Z)` 的**普通 5G LDPC 对照**列。共 81 个 SC 单元 + 9 个对照，全部数据存
`results_hm_*.json`。

```bash
python experiments_heatmap.py cell 0.8 32 100 2   # 单个 (R,Z,L,w)
python experiments_heatmap.py ctrl 0.8 32         # 对照
python experiments_heatmap.py render              # 9 张 exp_hm_<R>_w<w>.svg
```

**热力图结论**（每格 BER@工作点，中位数边际效应）：

| 旋钮 | R=0.7 | R=0.8 | R=0.9 | 结论 |
|:--:|:--:|:--:|:--:|:--|
| **Z**(码长) | Z16 5e-2→Z64 1e-2 | 1e-2→1e-3 | 1e-2→1e-2 | **越大越好**（干净，不改码率）；高码率 R0.9 收益变弱 |
| **w**(深度) | w1 2e-3 / w2 3e-2 / w3 1e-1 | w1 1e-3 / w3 6e-2 | w1 7e-3 / w3 3e-2 | **w=1 最优，w=3 差 30–60×**（深耦合把系统位边分得过稀+码率损失） |
| **L**(链长) | L30 2e-2→L300 5e-2 | 大致持平 | 持平 | 效应小且**有码率混淆**（长L码率略高→同Eb/N0更难）；本征影响微弱 |

- **最佳配置**：`大 Z + w=1 + L=30~100`。例 R0.8 `Z64,L30,w1` BER=**5.1e-5**，
  而普通 5G LDPC 对照(Z64)=2.6e-3 —— **SC 在 w=1 下比对照好约 50×**。
- **关键发现**：**SC 相对普通 5G LDPC 的增益强烈依赖耦合深度 w**。用 **w=1** 时 SC 明显
  胜过对照（~50×）；但 **w=2/3** 时 SC 反而可能**劣于**对照（5.4 节里我默认用 w=2，故当时
  测得的 SC 增益偏小 +0.12dB）。**超参搜索的价值正在于此：w=1 才是高码率的甜点。**
- **方法学注记**：单点 BER 热力图里 L/w 会改变码率，故 L 轴有混淆；但 w 轴结论稳健
  （w=3 码率更低却更差），Z 轴最干净（Z 不改码率）。

> 9 张图 `exp_hm_<R>_w<w>.svg`（行=Z，列=L+plain对照；绿=低BER更好），或 `results.html`；
> 全部数据 `results_hm_*.json`（81 SC + 9 对照）。

## 七、设计选择与局限

- **为何系统位边扩展？** 它在"忠于 5G NR 可编码结构"与"实现简单正确"之间取得
  平衡：每个位置仍是标准 5G 编码，且耦合校验矩阵 `H_SC·c=0` 严格成立（已验证）。
  完全边扩展（耦合所有边）理论上耦合更强，但需要对整张耦合矩阵做生成矩阵编码
  （规模过大）或更复杂的近似下三角编码，超出本演示范围。
- **阈值饱和是渐近性质**（`Z, L → ∞`）。本实现用中等规模（`Z=24, L=30`）演示
  有限长下的**耦合增益**与**译码波**，趋势与理论一致，但非渐近极限。
- **译码器**默认归一化最小和（`α=0.8`，5G 硬件常用），亦可选和积；消息做有限
  幅度截断以处理边界处出现的度-1 校验节点。
